# Hosts (`modules/hosts/`)

Five directories, one per machine. Each directory's `default.nix` is a flake
part that declares exactly one `flake.nixosConfigurations.<name>` entry by
calling the library's constructors ([`mkHost` / `mkRpiHost`](fleet/lib/hosts.md)).

| Host | Constructor | System | Modules (in order) |
| --- | --- | --- | --- |
| aria | `mkHost` | x86_64-linux | `_configuration`, `_hardware-configuration`, `_hyprland` |
| raysha | `mkHost` | x86_64-linux | `_hardware`, `_configuration`, `_hyprland` |
| talia | `mkHost` | x86_64-linux | `_hardware-configuration`, `_hyprland`, `_configuration` |
| eris | `mkRpiHost` | aarch64-linux | `_configuration`, `_hardware-configuration` |
| alanna | `mkRpiHost` | aarch64-linux | `_configuration`, `_hardware-configuration` |

## Why the files are prefixed `_`

`import-tree ./modules` imports *every* `.nix` under `modules/` as a flake
part. The per-host config files (`_configuration.nix`, `_hyprland.nix`, …) are
plain NixOS module functions — they must NOT be imported as flake parts. The
`_` prefix hides them from import-tree (the installer uses the same
convention). Only `default.nix` is a flake part in each host directory, and it
pulls the others in explicitly via `./_foo.nix` paths.

## Why the module *order* differs per host

Modules are merged in list order, and `mkHost` appends the feature modules
before the host's own modules (host config wins on plain assignments). Within
the host's own list, order still matters for plain (non-`mkDefault`)
assignments: raysha lists `_hardware.nix` first so `_configuration.nix` can
override hardware choices; talia lists `_configuration.nix` last for the same
reason in reverse. Note raysha's file is `_hardware.nix`, not
`_hardware-configuration.nix` — a deliberate shortening (its contents are
hand-written GPU/keyboard selections, not generator output).

## What each kind of file is

- **`_configuration.nix`** — the human layer: which features are enabled and
  with which parameters (`healthcheck.devices`, `streaming.desktops`,
  `backups.restic.repository`, …). This is the file you edit to change
  behavior.
- **`_hardware-configuration.nix`** (aria, talia, eris, alanna) — generated by
  `nixos-generate-config` / `nixos-installer install`: filesystems, kernel,
  UUIDs. Rarely edited by hand.
- **`_hyprland.nix`** (aria, raysha, talia) — per-host monitor setup: EDID
  blobs for the Philips TVs, monitor layout, scaling. (aria's comment
  `-- Philips TV`; raysha's `-- Philips TV: right of AOC`.)
- **`_hardware.nix`** (raysha) — GPU driver choice (`hardware-gpus.nvidia =
  true;`) and peripherals (`hardware.keyboard.qmk`). Note the option
  namespace gotcha: GPU options live under the top-level `hardware-gpus.*`
  namespace, not `hardware.gpus.*`.

## How the Pi hosts differ

eris and alanna call `mkRpiHost`, which asserts `system == "aarch64-linux"`,
marks `rpi = true` in the host table's mirror, swaps the `nixosSystem`
function to `inputs.nixos-raspberrypi.lib.nixosSystem`, and each `default.nix`
passes `extraArgs = { inherit (inputs) nixos-raspberrypi; }` so the
constructor can see the input it swaps in. Consequence for CI: `nix flake
check` skips aarch64 targets by default — use `--all-systems` to check eris
and alanna.

## Host identity wiring

`mkHost`'s tail module sets `ssh.server.enable` and `nixbuilder.buildServer`
from the [host table](fleet/lib/hosts.md) — so nothing in any `_configuration.nix`
turns a host into (or off) an ssh server or build server by hand; the table is
the single source of truth, and the assertion in `mkHost` keeps the table and
the constructors honest.
